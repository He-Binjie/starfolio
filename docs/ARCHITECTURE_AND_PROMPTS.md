# 星海拾卷（Starfolio）· 架构设计与核心 Prompt 约束说明

> 本文档说明「星海拾卷」的整体分层架构、**0-Token 本地计算管线**，以及最关键的 **BYOL 防幻觉问答 Prompt 约束与生成后审计机制**。

---

### 核心设计取舍（为什么这样做？）

1. **能用 0 Token 确定性算出来的，绝不交给大模型**：
   - 全文检索、中文语义匹配、文档聚类、2D 星图、血缘关系、双栏数值差异、事实矩阵、重复文件、冲突初筛全部在本机零成本完成（毫秒级响应、100% 离线、不泄露原文）。
   - 大模型只在真正需要「跨文档语义综合」与「歧义裁决」的两个环节介入：**围栏问答** 与 **冲突复核**。
2. **文件原地只读（Zero-Copy Read-Only）**：
   - 无论用户选整个目录还是从「下载」夹里挑 3 个零散 PDF，后端都不复制也不修改原文件，所有解析结果与向量都隔离存在应用数据目录的 SQLite 数据库中。
   - `config.py` 中的 `resolve_safe_path()` 是唯一的文件路径出口，防止目录穿越并强制叠加隐私关键词排除。

## 二、核心约束提示词（Prompt 原文与设计意图）

### 1. 知识库严格溯源问答 Prompt（`backend/app/qa.py`）

在用户点击「问 AI」（或勾选 2～8 份文档做「证据围栏」分析）时，后端先通过 **RRF 混合检索**召回 Top-K 证据片段，编号为 `[1]`～`[N]`，附上每条证据的**来源路径、行号/页码与章节路径**，再组装如下约束提示词：

```text
你是用户的本地知识库核对助手（严格只读模式）（如勾选围栏则注明：用户已手动限定以下 N 份文档作为回答围栏）。
请用中文先给结论、再给依据，回答用户问题。

必须遵守的规则：
1. 不要调用任何外部工具、不要读取额外文件、不要联网，严格只依据下方 [1]~[N] 证据片段作答。
2. 每一条事实论断、口径、数字、结论句末都必须用 [1] 或 [1][2] 标明引用的片段编号。
3. 如果证据里没有覆盖问题的某一部分，直接写「知识库召回片段中未找到相关依据」，绝不编造或靠常识补全数字。
4. 如果多个片段存在不同时间或不同版本的口径，请按日期/版本分别列出并标明出处 [n]。
5. 保持简洁克制，直接输出回答正文，不要寒暄。

[可选：最近 3 轮会话历史摘要，明确声明「仅用于理解指代，事实必须仍以最新证据 [1]~[N] 为准」]

## 知识库召回证据（共 N 条）
[1] 来源：{source_id}/{rel_path} (L{start}-L{end} 或 第{page}页 > {heading_path})
标题：{title}
内容：
{excerpt}
---
...

## 当前问题
{user_question}
```

#### 这套 Prompt 的 4 个关键防坑设计：
- **禁止工具逃逸（Rule 1）**：即使用户挂载的是本地 Agent CLI（如 Claude Code / Codex / agy），快问模式下也强制禁止调用外部工具，保证回答完全锁死在可控证据集内、耗时稳定。
- **句末强制锚点（Rule 2）**：每一条实质句末都带 `[n]`，前端才能把 `[n]` 渲染成可悬停预览摘录、点击直达原文件对应行号/页码的交互胶囊。
- **显式拒答出口（Rule 3）**：明确规定未命中时说「知识库召回片段中未找到相关依据」，防止模型用通识强行补全业务数字。
- **多版本口径并列（Rule 4）**：当新旧文档并存时，强制按时间/版本并列呈现而非“和稀泥”取平均。

### 2. 生成后确定性审计器（`audit_answer_citations` in `backend/app/qa.py`）

只靠 Prompt 约束模型是不够的——大模型仍可能漏标引用或偷偷编造数字。因此每次 AI 返回后，后端都会跑一道 **0-Token 确定性正则审计**：

1. **引用覆盖率（`citation_ratio`）**：逐行扫描实质性论断，统计带有效 `[n]` 引用行的占比；没有引用的行会在前端界面直接灰标 `未引用` 提醒人工复核。
2. **幻觉编号检测（`invalid_refs`）**：拦截模型输出超出召回范围的假编号（例如只给了 8 条证据却编出 `[12]`）。
3. **数字溯源告警（`number_warnings`）**：提取回答中所有带单位/量纲的数字（如 `5天`、`15%`、`200万`），逐一核对它是否真实出现在该句所引用的证据片段 `[n]` 原文中——若原文里根本没有这个数字，自动标红告警。

---

### 3. 口径冲突 AI 复核 Prompt（`backend/app/conflicts.py`）

前端点击「冲突初筛」时，先用 **0-Token 本地向量余弦相似度（≥ 0.80）+ 量化词差集**（如文档 A 含 `5天 / 10%`，文档 B 含 `7天 / 15%`）筛选出候选对；仅当用户主动点击某条的「AI 复核」时，才发送如下强约束 JSON Prompt：

```text
你是知识库口径审计助手（严格只读，不要调用任何工具）。
下面两段来自同一项目的不同文档，向量相似度很高但包含不同数值/日期。
请判断它们属于以下哪一类，并只输出一个 JSON 对象（不要额外解释）：
{"verdict": "真冲突" | "版本演进" | "非冲突", "reason": "一句话说明差异点及建议以哪份为准"}

## 文档 A：{rel_path_a} (L{start_a}-L{end_a})
{snippet_a}

## 文档 B：{rel_path_b} (L{start_b}-L{end_b})
{snippet_b}
```

## 三、0-Token 知识图谱与血缘算法要点

1. **文档血缘三层信号（`backend/app/lineage.py`）**：
   - **L1 显式链接（蓝色实线，最高优先级）**：解析 Markdown 相对链接与路径提及，自动建立 `被引用源头 → 引用者` 的确定性有向边。
   - **L2 版本与快照演进（琥珀实线）**：剥离文件名中的日期、`v1/v2/rev6`、`快照/归档` 后缀，将同项目同主题文档按时间串联成版本链。
   - **L3 阶段语义流向（翠绿虚线）**：按文档生命周期阶段（`调研与会议 → 决策与口径 → PRD与方案 → 执行与复盘`）结合同项目高向量相似度（≥ 0.74）推断上下游流向。
2. **2D 星海星图与聚类命名（`backend/app/vectors.py`）**：
   - 对文档级平均向量执行球面 K-Means 聚类 + SVD/PCA 降维投影到 2D 平面。
   - 聚类命名摒弃粗暴定长截断，改为优先提取目录 `INDEX.md` 友好名 + 按自然分隔符完整切词，避免中文标题拦腰截断。
